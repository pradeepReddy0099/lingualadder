LinguaLadder

Wikipedia search that ranks articles by how relevant they are and how well they fit your reading level, for learners of English and Spanish.

The problem

A search engine returns the most relevant pages, not the ones a learner can actually read. Someone learning Spanish who searches "volcán" gets the full encyclopedia article, packed with rare words and long sentences. Graded readers fix the level but not the topic. LinguaLadder tries to give learners both: articles about what they care about, at a level they can handle.

The big questions

Can we predict reading difficulty automatically?

Using only language-independent text features, with no hand labels beyond "easy" and "regular" encyclopedias.

Does it work across languages?

If the model is trained on English, does it still rank Spanish articles sensibly, and vice versa?

How much relevance do we give up?

Re-ranking for level moves results away from pure topical relevance. How big is that trade-off, and can we control it?

Can the system learn a learner's level?

Starting from a guessed level, can simple "too easy / too hard" feedback steer results toward what suits the reader?

Key takeaways

2.2×

More results at the right level

Level match rose from 0.162 with plain BM25 to 0.359 with pure level re-ranking (0.201 with the topic guard on).

0.888

Difficulty accuracy

Our 15-feature model vs 0.776 for sentence and word length alone (5-fold CV).

0.83–0.88

Transfers across languages

Trained on one language and tested on the other: 0.827 on Spanish, 0.884 on English.

−0.02

Relevance kept with a topic guard

Pure level re-ranking cost 0.15 nDCG@10 (0.919 to 0.771) by surfacing articles that only mention the query. Ranking on-topic articles first brings it back to 0.898.

−48%

Feedback finds the level

In simulation, feedback cut the gap to a learner's ideal difficulty from 0.264 to 0.136.

How it works

query ─► BM25 over the language's index (top 100 candidates)
      ─► topic guard: query words in the title or lead? on-topic first, passing mentions after
      ─► re-rank: a · relevance + (1 − a) · exp(−(difficulty − target)² / 2σ²)   (a = 0.5, σ = 0.15)
      ─► top 10 with level and CEFR badges ─► reader with highlight-to-translate
      ─► "too easy / too hard" feedback moves the learner's target level

Difficulty model. Logistic regression on 15 features (sentence length and spread, word length, syllables per word, share of rare and core-vocabulary words, type-token ratio, clause markers, digits, parentheses, article length), z-scored within each language. Easy labels come from Simple English Wikipedia and Vikidia.

Levels. Beginner below 0.35, Intermediate 0.35 to 0.65, Advanced above 0.65, with targets 0.20, 0.50 and 0.80, plus an approximate CEFR band (A1 to C2).

Data

1,748 articles on 50 seed topics (volcanoes, football, chocolate, Frida Kahlo, chess and more): 992 English and 756 Spanish, collected through the MediaWiki API from Wikipedia, Simple English Wikipedia and Vikidia. The raw JSONL files are in the repository's data/raw folder, with a description in data/README.md. Article text is CC BY-SA.

Run it yourself

git clone https://github.com/pradeepReddy0099/lingualadder.git
cd lingualadder
pip install -r requirements.txt      # Python 3.10+: flask, numpy, scikit-learn, scipy, ...
python -m lingualadder.build         # ~15 s
python app.py                        # http://127.0.0.1:5000

Full setup and how to reproduce every number are in the README. Or skip setup and use the browser demo, which runs the same ranking in JavaScript.

Limitations and next steps

Relevance labels are automatic (an article counts as relevant if it was collected for that topic), so true precision is probably higher. Level match uses our own difficulty scores; we also report a measure based on source labels. Adaptive feedback was tested on simulated learners, not real ones. Next: a small user study, comprehension checks, and ranking by the words a learner already knows.
